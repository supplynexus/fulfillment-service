# 安全指南

## 敏感信息管理

### 1. 环境变量
- 所有敏感配置应通过环境变量设置
- 不要将 `.env.local` 文件提交到版本控制
- 使用 `.env.example` 作为配置模板

### 2. 密钥管理
- 私钥文件存储在 `keys/` 目录
- 密钥文件已添加到 `.gitignore`
- 生产环境应使用更安全的密钥存储方式

### 3. 测试文件
- 测试文件中的敏感信息应通过环境变量或配置文件管理
- 不要硬编码用户名、密码、租户名等敏感信息
- 使用 `test-config.example.js` 作为测试配置模板

### 4. 代码审查
- 定期检查代码中的硬编码敏感信息
- 使用自动化工具扫描敏感信息泄露
- 确保所有敏感信息都通过环境变量管理

## 安全最佳实践

### 1. 开发环境
```bash
# 复制环境配置模板
cp environment.example .env.local

# 复制测试配置模板
cp test-config.example.js test-config.js

# 编辑配置文件，填入实际值
```

### 2. 生产环境
- 使用密钥管理服务（如AWS KMS、Azure Key Vault）
- 定期轮换密钥
- 使用强密码策略
- 启用多因素认证

### 3. 代码审查清单
- [ ] 检查硬编码的敏感信息
- [ ] 验证环境变量配置
- [ ] 确认密钥文件不被提交
- [ ] 检查测试文件中的敏感信息
- [ ] 验证API密钥和密码的安全性

## 紧急响应

如果发现敏感信息泄露：
1. 立即轮换相关密钥
2. 检查访问日志
3. 更新相关配置
4. 通知相关人员
5. 记录事件并改进流程
