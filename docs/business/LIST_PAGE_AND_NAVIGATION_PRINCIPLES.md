# 列表页与导航原则（业务知识）

本文档记录列表页设计原则、每条记录应有的跨实体链接、订单业务主流程与状态一致性要求，供前端实现与后续迭代对照。部分内容参考业界列表/筛选 UX 最佳实践（如 NN/g、React-Admin、电商订单后台）。

---

## 1. 列表页通用原则

### 1.1 上部：条件与筛选

- **位置**：列表页上部为筛选/条件区，与业务强相关。
- **原则**：
  - 筛选条件**可见、有标签、易发现**（可左侧边栏或顶部持久条）。
  - 支持**按状态、名称/关键词**等检索；不同列表业务不同，条件不同。
  - 当前生效条件建议用 **Chip/标签** 展示，支持单条件清除或「清除全部」。
  - 无结果时明确提示当前筛选并支持一键放宽/清除。
- **示例**：
  - **核心商品**：按状态（active/draft 等）、名称/关键词、类型、供应商等。
  - **核心订单**：按订单号/关键词、商品、状态、履约状态、地址校验状态等。
  - **SCM 订单**：按状态、来源订单、Printify 绑定状态等。
  - **Printify/Shopify 商品**：按店铺、发布状态、同步状态、名称检索等。

### 1.2 每条记录：链接与可迁移性

- **原则**：列表每一行应提供**多种链接**，能迁移到相关页面；可用 **URL 跳转**（可分享、可书签）或 **弹窗**（轻量、不离开列表），由场景决定。
- **链接类型**：
  - **本实体详情**：详情页或详情弹窗（同一控件、可路由可弹窗）。
  - **下游/上游业务**：如核心商品 → 核心订单（包含该商品的订单）、SCM 订单（该商品发货情况）、上游 Shopify 商品、下游 Printify 商品。
  - **外部系统**：本系统「外部系统同步表」的表示画面 + **直接 link 到外部系统**（如 Printify 后台、Shopify 后台）。

## 2. 核心商品列表应有的链接与筛选

### 2.1 筛选（上部）

- 按**状态**、**名称/关键词**检索；可选：类型、供应商等（与现有或后端能力对齐）。

### 2.2 每条记录应有或建议的链接

| 目标 | 说明 | 实现方式建议 |
|------|------|----------------|
| 核心商品详情 | 本系统商品详情 | 路由 `/products/{id}` 或弹窗（若统一控件） |
| 核心订单 | 购买了包含该核心商品的订单 | 路由 `/orders?product={core_product_hashid}`（已支持） |
| SCM 订单 | 包含该商品履约的 SCM 订单 | 路由 `/scm-orders?product={core_product_hashid}` 或后续后端支持后加 |
| 商品映射（Printify） | 去 Printify 映射页绑定/查看 | 路由 `/product-mapping/printify?core_product_id={hashid}` |
| 商品映射（Shopify） | 去 Shopify 映射页 | 路由 `/product-mapping/shopify?core_product_id=...`（若有） |
| 外部系统同步表 | 本系统「外部系统商品」列表/详情（如 Printify 本地商品） | 路由或弹窗，并 **直链外部系统**（如 Printify 商品页） |

- **本系统外部商品画面**：例如 Printify 本地商品列表 + 实时商品详情（弹窗/路由），并提供「打开 Printify 后台」等外链。
- **直链外部系统**：每条可提供「打开 Shopify 商品」「打开 Printify 商品」等（新开标签）。

## 3. 订单列表页：业务主内容

订单列表是业务主内容，**链接与操作应更多**。

### 3.1 主流程与依赖（业务知识）

1. **Shopify 订单 → 核心订单（core）**
   - Shopify 订单随时读入到本系统核心订单（已支持）。
   - 列表/详情需能跳转：核心订单 → 来源 Shopify 订单（外链或内部展示）。

2. **核心订单 → SCM 订单**
   - 通过勾选核心订单中的**商品行**生成 SCM 订单。
   - **前置条件**：若商品**未绑定**（无 core 商品或 core 商品未正确配置），则无法生成 SCM 订单，需**先创建/维护核心商品**再操作。
   - 列表应能：核心订单 → 关联 SCM 订单（若有）；SCM 订单 → 来源核心订单。

3. **SCM 订单 ↔ Printify**
   - **当前业务**：较多从 Printify 订单反查并绑定到 SCM。
   - **正向业务**：核心 SCM 订单 → **生成 Printify 订单**；此时要求 **core 商品与 Printify 商品已绑定**，否则无法生成 Printify 订单。
   - 列表应能：SCM 订单 → Printify 订单（外链或内部）；订单状态与 Printify/Shopify 一致（见下节）。

### 3.2 订单列表应有的链接与操作（检查清单）

- 核心订单：详情、按商品筛选的订单列表、关联 SCM 订单、Shopify 来源（外链）、批量更新 Shopify 状态等。
- SCM 订单：详情、来源核心订单、Printify 订单（外链）、物流跟踪等。
- Printify/Shopify 订单列表：各自详情、同步到 core、状态展示与一致性（见 4）。

## 4. 订单状态统一与一致性

### 4.1 原则

- **Shopify 订单、Printify 订单、核心订单（core）的状态应统一或一致**，不在同一条业务链上出现相互矛盾的状态展示。
- 同步与展示逻辑需保证：从 Shopify/Printify 读入或回写后，本系统展示的状态与外部系统可解释、不冲突。

### 4.2 现状与 Mapping

- **Shopify 订单随时读入**：已支持，可随时同步到核心订单。
- **Printify 订单随时读入**：已支持，可随时同步/展示。
- **Mapping**：
  - 核心商品 ↔ Printify 商品：通过「商品映射」与「自动按 Shopify 绑定 Printify」等能力维护；列表与详情应提供「去映射页」等入口。
  - 核心商品 ↔ Shopify 商品：若有对应映射与列表，也应提供链接与直链外部系统。
- 若发现某处「状态矛盾」或「无法生成某类订单」，优先检查：**商品是否已绑定、状态同步任务是否正常、展示是否取错字段**。

### 4.3 当前状态（Shopify/Printify 读入与 Mapping）

- **Shopify 订单随时读入**：已支持，可随时同步到核心订单。
- **Printify 订单随时读入**：已支持，可随时同步/展示。
- **Mapping**：
  - 核心商品 ↔ Printify 商品：支持手动映射与「按 Shopify 自动绑定 Printify」；列表与详情已提供「管理映射」「Printify 映射页」等入口。
  - 核心商品 ↔ Shopify 商品：若有对应数据与接口，同样应提供映射入口与直链。
- 若遇「无法生成 SCM/Printify 订单」，优先确认：该核心商品是否已与对应外部商品绑定、自动化/同步任务是否正常。

## 5. 各列表页检查清单（现状对照）

供实现与回归时逐项对照。

| 列表页 | 上部筛选/条件 | 行内链接/操作 | 备注 |
|--------|----------------|----------------|------|
| 核心商品 | 有：搜索、状态 | 详情、编辑、订单?product=、管理映射（弹窗）、**Printify 映射页**（`/product-mapping/printify?core_product_id=`）；建议补：SCM 按商品（待后端） | 见 2.2 |
| 核心订单 | 有：搜索、按商品 | 详情、SCM 订单、外链 Shopify、Printify 等 | 订单主流程见 3 |
| SCM 订单 | 有 | 详情、来源核心订单、Printify 外链、跟踪 | 见 3.2 |
| Printify 实时商品 | 店铺、发布状态、同步状态、检索 | 详情（弹窗/路由）、外部 Printify、映射 | 已有 |
| Printify 本地商品 | 店铺、检索 | 外部链接、系统详情、去绑定（映射页） | 已有 |
| Shopify 商品/订单 | （按现有实现） | 外链、同步、映射等 | 按现有与 2/3 对齐 |
| 商品映射（Printify/Shopify） | 按平台 | 到核心商品、到外部商品、绑定/解绑 | 已有 |
