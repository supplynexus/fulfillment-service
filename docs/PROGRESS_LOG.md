# SupplyNexus Fulfillment Service - 项目进度日志

## 项目概述
SupplyNexus 是一个基于 FastAPI + Next.js 的 Shopify 到 Printify 订单履行自动化系统，支持多租户架构和完整的认证系统。

## 最新更新 (2025-08-25)

### 🔄 认证系统重构完成

#### 重构背景
原有的认证系统过于复杂，包含多个数据库表和不同的认证方式，导致维护困难。决定进行架构简化。

#### 主要变更
1. **数据库表清理**
   - 删除 `system_keys` 表（改用环境变量管理）
   - 删除 `api_keys` 表（业务API不再使用API密钥认证）
   - 删除 `api_key_access_logs` 表
   - 删除 `user_keys` 表（统一使用租户级别密钥）

2. **认证方式统一**
   - 所有业务API统一使用租户级别RSA签名认证
   - 系统API保留简单的API密钥认证（环境变量）
   - 健康检查保留独立的健康检查认证

3. **密钥管理简化**
   - 前端存储租户私钥，用于生成签名
   - 后端存储租户公钥，用于验证签名
   - 数据库只在 `tenants` 表中存储公钥

4. **算法匹配修复**
   - 前端和后端统一使用 RSA-SHA256 + PKCS1v15 填充
   - 修复了签名验证不匹配的问题

#### 开发工具优化
1. **工具重组**
   - 将所有开发工具移动到 `backend/scripts/` 目录
   - 为每个工具创建对应的 shell 脚本
   - 完善工具文档和使用说明

2. **新增工具**
   - `quick_check.sh` - 快速代码检查
   - `check_imports.sh` - 详细导入检查
   - `check_syntax.sh` - 语法检查
   - `check_code_quality.sh` - 全面质量检查
   - `update_tenant_public_key.sh` - 租户公钥更新

3. **代码质量改进**
   - 修复所有导入错误和语法问题
   - 添加 pre-commit 配置
   - 优化日志记录和错误处理

#### 数据库迁移
- 应用所有清理相关的迁移
- 数据库架构已更新到最新状态
- 认证系统正常工作

#### 部署影响

- 密钥管理更加集中

### 🔧 技术实现细节

#### 认证流程（重构后）
1. 前端接收用户登录信息
2. 生成RSA签名（使用租户私钥）
3. 发送请求到后端API
4. 后端验证签名和用户凭据（使用租户公钥）
5. 返回用户信息给前端
6. 前端生成JWT令牌（使用前端私钥）
7. 存储令牌到localStorage

#### 安全机制
- **RSA签名**: 防止请求篡改（统一算法）
- **JWT令牌**: 无状态会话管理
- **密码加密**: bcrypt哈希
- **登录锁定**: 失败次数限制
- **CORS配置**: 跨域请求控制
- **主机验证**: 开发环境放宽，生产环境严格

#### Docker配置
- **前端**: 端口3000，密钥挂载，日志挂载
- **后端**: 端口8000，数据库连接，Redis连接
- **网络**: host.docker.internal通信
- **环境**: 开发环境配置
